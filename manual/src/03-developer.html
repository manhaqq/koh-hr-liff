จุดที่พลาดกันบ่อยที่สุด

clasp push ไม่ได้ ทำให้ของจริงเปลี่ยน มันแค่อัปโหลดโค้ดขึ้นไปเก็บไว้ Web App ที่พนักงานใช้ยังรันเวอร์ชันเดิมอยู่ จนกว่าจะสร้างเวอร์ชันใหม่แล้วชี้ deployment ไปหามัน ซึ่ง scripts/release.sh ทำให้ครบทุกขั้นแล้ว

ทำไม URL ของ deployment ห้ามเปลี่ยน

URL /exec ถูกฝังไว้ 2 ที่ที่แก้ยาก คือใน config.js ซึ่งเสิร์ฟให้ทุกเบราว์เซอร์ และในช่อง Webhook URL ของ LINE Developers Console ถ้าสร้าง deployment ใหม่ URL จะเปลี่ยน แล้วทั้งเว็บและ webhook จะพังพร้อมกัน

วิธีที่ถูกต้องคือ ชี้ deployment เดิมไปยังเวอร์ชันใหม่ รหัส deployment ที่ใช้งานจริงถูกเขียนตายตัวไว้ในตัวแปร LIVE_DEPLOYMENT ทั้งใน scripts/release.sh และ scripts/rollback.sh

หลักการ 0 บาท — สิ่งที่ห้ามทำลาย

แพ็กเกจฟรีของ LINE ส่งข้อความ push ได้ 300 ข้อความต่อเดือน พนักงาน 60 คนหมายความว่าแจ้งเตือนได้เพียง 5 ครั้งต่อเดือน เท่านั้น ระบบทั้งหมดจึงออกแบบมาเพื่อไม่ใช้ push เลย

แทนที่จะระบบทำแบบนี้ต้นทุน
ส่งข้อความว่ามีประกาศใหม่สลับภาพ Rich Menu ให้ขึ้นจุดแดงฟรี ไม่จำกัด
ส่งข้อความเตือนเข้ากะพนักงานกดเพิ่มลงปฏิทิน มือถือเตือนเองฟรี
ส่งข้อความบอก HR ว่ามีเรื่องใหม่ส่งอีเมลฟรี
ตอบข้อความในแชทใช้ reply token ไม่ใช่ pushฟรี
ก่อนเพิ่มฟีเจอร์ใด ๆ ให้ถามข้อนี้เสมอ

ฟีเจอร์นี้ต้องส่งข้อความ push หรือเปล่า ถ้าใช่ แปลว่าคิดผิดทาง ให้กลับไปดูว่าจะใช้จุดแดง อีเมล หรือ reply token แทนได้ไหม การเผลอเพิ่ม push เพียงจุดเดียวจะทำให้โควตาหมดภายในไม่กี่วัน แล้วระบบทั้งระบบจะเงียบไปทั้งเดือนโดยไม่มีใครรู้ว่าเพราะอะไร

โควตา 300 ข้อความถูกเก็บไว้ทั้งก้อนสำหรับเหตุด่วนจริง ๆ ผ่านเมนู 🔴 ส่งด่วนเข้าแชททุกคน เท่านั้น

ปล่อยเวอร์ชันใหม่

./scripts/release.sh v0.4.0 "เพิ่มระบบข้อสอบ"

สคริปต์ทำ 5 ขั้นตามลำดับนี้

  1. สร้างภาพ Rich Menu ใหม่จากไฟล์ออกแบบ แล้ว commit ถ้าภาพเปลี่ยน
  2. clasp push อัปโหลดโค้ดหลังบ้าน
  3. clasp version สร้างเวอร์ชันถาวรที่ย้อนกลับมาได้
  4. ชี้ deployment เดิมไปยังเวอร์ชันใหม่ — URL ไม่เปลี่ยน
  5. ติด git tag แล้ว push ขึ้น GitHub ซึ่งจะ deploy หน้าเว็บเอง
หลังปล่อยเวอร์ชัน ต้องทำมืออีก 2 อย่าง

1. ถ้าภาพ Rich Menu เปลี่ยน ให้เปิดชีตแล้วกดเมนู 🎛️ Rich Menu → สร้าง/อัปเดต Rich Menu ทั้งหมด

2. ถ้ามีทริกเกอร์หรือ oauth scope ใหม่ ให้กดเมนู ⏰ ติดตั้งงานอัตโนมัติ และกด Authorize ใหม่ ทำตอนร้านไม่ยุ่ง เพราะระหว่างที่ยังไม่ authorize ระบบจะหยุดทำงาน

ย้อนกลับเวอร์ชันเก่า

./scripts/rollback.sh              # ดูรายการเวอร์ชัน
./scripts/rollback.sh v0.3.0       # ย้อนกลับ

ฝั่งหลังบ้านย้อนได้ทันทีโดยไม่ต้องแตะโค้ดเลย เพราะ Apps Script เก็บทุกเวอร์ชันไว้ถาวร แค่ชี้ deployment เดิมกลับไปเวอร์ชันเก่า ใช้เวลาไม่กี่วินาที และ URL ไม่เปลี่ยน พนักงานไม่รู้สึกว่ามีอะไรสะดุด

ฝั่งหน้าเว็บใช้ git revert ไม่ใช่ git checkout แล้ว force push เพราะ force push จาก detached HEAD จะลบ commit ทั้งหมดหลังแท็กนั้นทิ้งถาวร ซึ่งเป็นการทำลายข้อมูล ไม่ใช่การย้อนกลับ ส่วน revert สร้าง commit ใหม่ที่ย้อนการเปลี่ยนแปลง ประวัติยังอยู่ครบและย้อนซ้ำได้อีก

กฎเหล็ก 6 ข้อ

  1. ห้ามเปลี่ยนชื่อคอลัมน์แถวที่ 1 — โค้ดอ่านชื่อคอลัมน์ตรง ๆ เปลี่ยนเมื่อไหร่ฟิลด์นั้นจะกลายเป็นค่าว่างแบบเงียบ ๆ ระบบยังทำงานต่อได้แต่ข้อมูลหายหมด ซึ่งหาสาเหตุยากมาก
  2. ห้ามลบแถวพนักงานที่ลาออก — กฎหมายแรงงานไทยให้เก็บทะเบียนลูกจ้างอย่างน้อย 2 ปี ให้ใช้เมนูตัดสิทธิ์แทน
  3. ห้ามใส่เลขบัตรประชาชน — เก็บได้แค่เบอร์โทร 4 ตัวท้ายในคอลัมน์ phoneLast4
  4. ห้ามใส่เงินเดือน — ให้แยกไฟล์ที่จำกัดสิทธิ์ต่างหาก
  5. ห้ามแชร์แบบ "ทุกคนที่มีลิงก์" — เฉพาะ HR และผู้บริหาร
  6. lineUserId ห้ามออกนอกไฟล์นี้ — เป็นข้อมูลส่วนบุคคลตาม PDPA ห้ามส่งกลับใน API ห้ามแสดงบนหน้าจอ ห้ามเขียนลง log ห้ามใส่ในข้อความ error

เพิ่มคอลัมน์หรือแท็บใหม่

เพิ่มได้ แต่ต่อท้ายเท่านั้น ห้ามแทรกตรงกลางและห้ามสลับลำดับ และให้เขียนฟังก์ชัน ensureXxxSheets() ของตัวเองที่สร้างแท็บเฉพาะเมื่อยังไม่มี

อย่าใช้ initDatabase() เพื่อเพิ่มคอลัมน์

initDatabase() เขียนทับแถวที่ 1 ถ้าโครงสร้างจริงไม่ตรงกับที่โค้ดคาดไว้ หัวคอลัมน์อาจถูกเขียนผิดตำแหน่ง แล้วข้อมูลทั้งแท็บจะอ่านผิดทั้งหมด ต้องสำรองชีตทั้งไฟล์ก่อนรันเสมอ

เรื่องวันที่ที่ต้องระวัง

Google Sheets มักแปลงข้อความ 2026-08-25 เป็นวันที่จริงโดยอัตโนมัติ แล้วแสดงตามรูปแบบภาษาของไฟล์ เช่น 25/8/2026 ซึ่งจะทำให้การเปรียบเทียบวันที่พังทั้งระบบ ฟังก์ชัน cellToString_() ใน 02_Data.js จึงบังคับให้ทุกวันที่กลับมาเป็น yyyy-MM-dd และเวลาเป็น HH:mm เสมอ อย่าถอดออก

แคชถูกล้างเมื่อไหร่

คีย์ของแคชผูกกับ "เลขเวอร์ชันของตาราง" การล้างจึงทำโดยเปลี่ยนเลขนั้น ซึ่งเกิดได้ 3 ทาง

  1. ตอนโค้ดเขียนข้อมูล — appendRow() และ updateRow() เรียก bumpTableVersion_() ให้เอง
  2. ตอนคนแก้ชีตด้วยมือ — ทริกเกอร์ onEditInvalidateCache ★ ข้อนี้สำคัญที่สุด เพราะ HR แก้ชีตโดยตรงเป็นเรื่องปกติของระบบนี้ ซึ่งไม่ผ่านโค้ดฝั่งเขียนเลย
  3. อายุหมดเอง — กันพลาดถ้าสองข้อบนไม่ทำงาน
อาการ "แก้ในชีตแล้ว แต่หน้าเว็บยังเป็นข้อมูลเก่า"

เกือบทุกครั้งแปลว่าทริกเกอร์ onEditInvalidateCache ไม่ได้ติดตั้ง ให้เปิดชีตแล้วกด ⏰ ติดตั้งงานอัตโนมัติ ใหม่ หรือถ้าต้องการล้างทันทีทั้งหมด ให้รันฟังก์ชัน clearAllTableCache() ใน editor

ถ้าอยากอ่านข้ามแคชในโค้ด ใช้ readTable(ชื่อแท็บ, true)

ทำไม updateRow ยังเขียนทีละเซลล์

ดูเหมือนช้าและน่าจะรวบเป็นครั้งเดียวได้ แต่ทำไม่ได้โดยตั้งใจ เพราะบางแท็บมีคอลัมน์สรุปที่เป็นสูตร ถ้าอ่านทั้งแถวแล้วเขียนกลับด้วย setValues สูตรจะถูกทับด้วยค่าคงที่และหายไปถาวร

พิกัดปุ่มอยู่ที่ richMenuMainObject_ ใน apps-script/08_RichMenu.js และไม่ได้ผูกกับภาพเลย ถ้าอัปโหลดภาพใหม่โดยไม่แก้พิกัด กดโลโก้จะกลายเป็นเปิดประกาศ กดประกาศจะเปิดคู่มือ สลับกันหมดทั้ง 60 คน โดยไม่มี error อะไรขึ้นมาเลย ไม่มีเทสต์ตัวไหนจับได้ ต้องเปิดไลน์กดดูเองทุกปุ่ม

ภาพดึงจาก GitHub Pages โดยตรง ไม่ต้องตั้ง Drive File ID ทีละไฟล์อีกแล้ว เปลี่ยนที่เก็บได้ด้วย Script Property ชื่อ RICHMENU_IMG_BASE_URL

ข้อจำกัดของ LINE คือภาพต้องไม่เกิน 1 MB ต่อไฟล์ build.py จึงบันทึกเป็น JPEG คุณภาพ 92 ซึ่งได้ประมาณ 365 KB ถ้าภาพใหม่ใหญ่เกิน ให้ลดค่า QUALITY ใน build.py

ความปลอดภัย — ปิดแล้วอะไร ยังเปิดอยู่อะไร

ปิดไปแล้ว

Formula injection ในชีต

Google Sheets ถือว่าข้อความที่ขึ้นต้นด้วย = + - @ คือสูตร ไม่ใช่ข้อความ ผู้โจมตีที่มีแค่บัญชี LINE (ไม่ต้องเป็นพนักงาน) จึงตั้งชื่อ LINE ตัวเองเป็นสูตร IMPORTXML ที่อ่านทั้งแท็บ Employees แล้วส่งออกไปเว็บของตัวเองได้ พอ HR เปิดชีต สูตรทำงานเองทันทีโดยไม่ต้องกดอะไร

ปิดด้วย safeCell_() ใน 02_Data.js ที่เติม ' นำหน้าค่าที่ขึ้นต้นด้วยอักขระเหล่านั้นก่อนเขียนทุกครั้ง ทุกการเขียนต้องผ่าน appendRow() หรือ updateRow() เท่านั้น ห้ามเรียก setValue() ใส่ข้อมูลจากผู้ใช้โดยตรง เพราะจะเปิดช่องโหว่นี้กลับมา

ขอบเขตสิทธิ์ Google Drive

เดิมใช้ drive.readonly ซึ่งให้สิทธิ์อ่าน Drive ทั้งบัญชีของเจ้าของ บน Web App ที่เปิดให้เข้าถึงแบบไม่ระบุตัวตน ตอนนี้แคบลงเหลือ drive.file ซึ่งเข้าถึงได้เฉพาะไฟล์ที่สคริปต์สร้างเอง

ยังเปิดอยู่ — ต้องตัดสินใจ

การตรวจลายเซ็น webhook ไม่เคยทำงานเลย

โค้ดใน 05_Webhook.js อ่านลายเซ็นจาก query string แต่ LINE ส่งมาใน HTTP header x-line-signature ซึ่ง doPost ของ Apps Script อ่านไม่ได้ ตัวแปรจึงเป็น null เสมอ และเงื่อนไขตรวจสอบไม่เคยทำงาน

ผลคือใครที่รู้ URL /exec (ซึ่งอยู่ใน config.js ที่เสิร์ฟให้ทุกเบราว์เซอร์) สามารถปลอมเหตุการณ์ได้ เขาจะไม่ได้ข้อมูลกลับไป แต่สั่งล้างจุดแดงของพนักงานคนอื่น และเขียนแถวขยะลง AuditLog ได้ไม่จำกัด

วิธีแก้: วาง Cloudflare Worker (ประมาณ 20 บรรทัด ฟรี) คั่นหน้า /exec ให้ตรวจลายเซ็นแล้วส่งต่อ โดยแนบลายเซ็นมาเป็น ?sig= ซึ่งเป็นสิ่งที่โค้ดปัจจุบันรออยู่แล้ว — ท่อต่อไว้ครบแล้ว ขาดแค่ตัว proxy

สิ่งที่ออกแบบไว้ดีแล้ว อย่าไปรื้อ

  • ทุกคำขอ API ตรวจ ID token กับ LINE ที่เดียวก่อนเข้า switch จึงไม่มี endpoint ไหนลืมตรวจได้
  • ตัวตนถูกดึงจาก token ฝั่งเซิร์ฟเวอร์เสมอ ไม่เคยเชื่อ empCode ที่ส่งมาจาก client
  • publicEmp_() คัดเฉพาะฟิลด์ที่อนุญาต และเขียนคอมเมนต์ระบุชัดว่าไม่ส่งอะไรบ้าง
  • ผังองค์กรตัดสถานะพนักงานทิ้ง 2 ชั้น เพื่อไม่ให้คนอื่นรู้ว่าเพื่อนถูกพักงาน
  • หน้ายืนยันตัวตนตอบข้อความผิดพลาดเหมือนกันหมดทุกกรณี เพื่อไม่ให้ใช้เดารายชื่อพนักงานได้ และไม่รวมคนที่ลาออกแล้ว เพื่อไม่ให้ยืนยันได้ว่าใครเคยทำงานที่นี่
  • รายงานที่ต้องใช้สิทธิ์ ตรวจ role ซ้ำในโค้ดอีกชั้น ไม่เชื่อคอลัมน์ audience ในชีตอย่างเดียว เพราะ HR แก้ชีตนั้นได้ และการพิมพ์ผิดไม่ควรกลายเป็นข้อมูลรั่ว

สำรองข้อมูล และกู้คืนลงเครื่อง

ประวัติเวอร์ชันของ Google Sheets ไม่ใช่การสำรองข้อมูล

มันอยู่ในไฟล์เดียวกันและตายไปพร้อมกับบัญชี ถ้าบัญชีถูกระงับ ถูกลบ หรือคนที่ถือบัญชีลาออก ข้อมูลหายทั้งหมดพร้อมกัน ในขณะที่กฎหมายแรงงานไทยกำหนดให้เก็บทะเบียนลูกจ้างอย่างน้อย 2 ปี

  2. เมนู ไฟล์ → ดาวน์โหลด → Microsoft Excel (.xlsx)

กู้คืนข้อมูล

  1. เปิดสำเนาที่ต้องการใน Drive แล้วเลือก ไฟล์ → สร้างสำเนา
  2. คัดลอก ID ของไฟล์ใหม่จาก URL
  3. เปิด Apps Script → ⚙️ Project Settings → Script Properties แล้วเปลี่ยนค่า SPREADSHEET_ID ให้ชี้ไฟล์ใหม่
  4. รัน clearAllTableCache() เพื่อล้างแคชของไฟล์เก่า
  5. เปิดชีตใหม่แล้วกด ② ตรวจสอบการตั้งค่า ว่าครบทุกรายการ
  6. ทดสอบเปิดหน้าเว็บจากไลน์จริงหนึ่งครั้งก่อนประกาศให้พนักงานใช้
ความเสี่ยงที่ยังไม่มีใครแก้ได้นอกจากเจ้าของ

ทั้งชีต สคริปต์ ทริกเกอร์ โควตาอีเมล และโฟลเดอร์สำรอง อยู่ในบัญชี Gmail ส่วนบุคคลบัญชีเดียวทั้งหมด บัญชีส่วนบุคคลไม่มีผู้ดูแลระดับองค์กร ไม่มีผู้ติดต่อสำรอง ถ้าบัญชีถูกระงับหรือคนที่ถือลาออก ร้านจะเข้าถึงข้อมูลไม่ได้อีกเลย

ควรทำอย่างน้อยหนึ่งข้อ — เพิ่มบัญชีที่สองเป็นเจ้าของร่วมของทั้งชีตและ Apps Script project, ย้ายไปใช้ Google Workspace ของร้านซึ่งกู้บัญชีได้จากผู้ดูแล, หรือตั้งผู้ติดต่อสำรองในบัญชี Google

รับมือเหตุขัดข้อง

พนักงานทุกคนเปิดหน้าเว็บไม่ได้

  1. ทดสอบ URL หลังบ้านก่อน — เปิดชีตแล้วกด ③ 🩺 ตรวจ Webhook URL
  2. ถ้าขึ้น error เรื่องสิทธิ์ แปลว่า oauth scope เปลี่ยนแล้วยังไม่ได้ authorize ให้เปิด Apps Script editor รันฟังก์ชันอะไรก็ได้หนึ่งครั้งแล้วกดยอมรับ
  3. ถ้ายังไม่หาย ให้ย้อนหลังบ้านกลับเวอร์ชันก่อนหน้า ./scripts/rollback.sh — ใช้เวลาไม่กี่วินาทีและ URL ไม่เปลี่ยน
  4. ดู execution log ใน Apps Script editor เพื่อหาสาเหตุที่แท้จริงทีหลัง

กดปุ่มในเมนูไลน์แล้วไปผิดหน้า

แปลว่าอัปโหลดภาพเมนูใหม่โดยไม่ได้แก้พิกัดใน richMenuMainObject_ ให้แก้พิกัดให้ตรงกับภาพ แล้วกดสร้างเมนูใหม่ทั้งหมด

จุดแดงไม่ขึ้น ทั้งที่มีประกาศใหม่

  1. เปิดชีตกด 🎛️ Rich Menu → ดูรายการ Rich Menu ปัจจุบัน ตรวจว่ามีครบทั้ง 5 ชุดและ ID ถูกบันทึกไว้
  2. ถ้าขาดชุดใดชุดหนึ่ง การติดจุดแดงจะไม่ทำงานแบบเงียบ ๆ ให้กด สร้าง/อัปเดต Rich Menu ทั้งหมด
  3. ถ้ายังไม่ขึ้นเฉพาะบางคน ให้กด 🔄 ล้างจุดแดงทุกคน แล้วลองใหม่

แก้ในชีตแล้วหน้าเว็บยังเป็นข้อมูลเก่า

ทริกเกอร์ล้างแคชไม่ได้ติดตั้ง กด ⏰ ติดตั้งงานอัตโนมัติ ใหม่ หรือรัน clearAllTableCache() เพื่อล้างทันที

ตารางกะที่หัวหน้าแก้หายไป

เป็นพฤติกรรมของ generateScheduleFromPattern() ซึ่งเก็บแถวไว้เฉพาะเมื่อคอลัมน์ status เป็นคำว่า manual ตัวพิมพ์เล็กเป๊ะ ๆ เท่านั้น แถวอื่นในช่วงที่สร้างใหม่จะถูกลบและสร้างจาก ShiftPattern ทั้งหมด

กู้ได้จาก ไฟล์ → ประวัติเวอร์ชัน ในชีต ถ้าเพิ่งเกิด หรือจากไฟล์สำรองรายสัปดาห์
