# รูปแนบในประกาศ

เอกสารนี้มี 2 ส่วน — **ส่วนที่ 1 เอาไปใส่คู่มือ HR ได้เลย** ส่วนที่ 2 สำหรับคนดูแลระบบ

---

# ส่วนที่ 1 — สำหรับคู่มือ HR

## ⚠️ กฎข้อเดียวที่ห้ามลืม

> ## รูปที่แนบในประกาศ **เปิดดูได้โดยไม่ต้องล็อกอิน**
> ## ใครก็ตามที่มีลิงก์ เปิดดูได้ทันที ไม่ต้องเป็นพนักงาน ไม่ต้องมีบัญชีอะไรเลย
>
> ## ❌ ห้ามถ่ายเอกสารที่มีข้อมูลส่วนบุคคลมาแนบเด็ดขาด

ตัวอย่างที่ **ห้ามแนบ**

- บัตรประชาชน ทะเบียนบ้าน พาสปอร์ต ใบขับขี่
- ใบรับรองแพทย์ ใบลา ใบเตือน หนังสือสัญญาจ้าง
- สลิปเงินเดือน หน้าสมุดบัญชีธนาคาร
- ตารางเวรที่มีชื่อ-นามสกุลเต็มและเบอร์โทรของพนักงาน
- หน้าจอคอมพิวเตอร์ที่เปิดชีตฐานข้อมูลค้างอยู่

**ทำไมถึงต้องเป็นแบบนี้** — ไม่ใช่เพราะระบบตั้งค่าไม่ดี แต่เพราะเซิร์ฟเวอร์ของ LINE
ต้องโหลดรูปเองเพื่อเอาไปแสดงในแชท มันไม่ได้ล็อกอินบัญชี Google ของร้าน
ถ้าตั้งรูปเป็นส่วนตัว รูปจะไม่ขึ้นเลยทั้งระบบ **นี่คือข้อแลกเปลี่ยนที่หลบไม่ได้**

---

## วิธีแนบรูป (ทำจากมือถือ จบใน 2 ขั้นตอน)

1. เปิดแชท LINE ของ **โก๋ในซอย HR Hub** แล้ว **ส่งรูปเข้าไปตรง ๆ** เหมือนส่งรูปให้เพื่อน
2. ระบบจะตอบกลับเป็นรายการ **ประกาศ 5 ฉบับล่าสุด** → **แตะฉบับที่ต้องการ** → เสร็จ

รูปจะขึ้นทั้งในการ์ดประกาศในแชท และในหน้า "ประกาศและข่าวสาร" ทันที
ไม่ต้องคัดลอกลิงก์ ไม่ต้องเข้า Google Drive ไม่ต้องแตะชีต

### ข้อกำหนดของไฟล์

| หัวข้อ | ค่า |
| --- | --- |
| ชนิดไฟล์ | JPG หรือ PNG เท่านั้น |
| ขนาดไฟล์ | ไม่เกิน 10 MB (รูปจากกล้องมือถือปกติผ่านสบาย) |
| สัดส่วนที่สวยที่สุด | แนวนอน ประมาณ 20:13 — รูปแนวตั้งจะถูกครอบบน-ล่าง |

### ถ้าไม่ขึ้นตามที่คิด

| อาการ | สาเหตุ |
| --- | --- |
| ส่งรูปแล้วระบบตอบว่า "รับเฉพาะข้อความตัวอักษร" | บัญชีของคุณยังไม่ได้ตั้งเป็น hr หรือ admin ในชีต Employees |
| ตอบว่า "ยังไม่มีประกาศให้แนบ" | ต้องมีแถวประกาศในชีตก่อน แล้วค่อยส่งรูปเข้ามาใหม่ |
| แตะเลือกแล้วบอกว่า "รูปนี้หมดอายุแล้ว" | เว้นนานเกิน 15 นาทีหลังส่งรูป — ส่งรูปเข้ามาใหม่ได้เลย |
| รูปไม่ขึ้นในหน้าประกาศ | ไฟล์อาจถูกลบไปแล้ว ระบบจะแสดงเป็นประกาศข้อความล้วนแทน ไม่มีรูปแตก |

---

## วิธี "ถอนรูป" ออก (ต้องรู้)

ถ้าเผลอแนบรูปผิด หรือมีพนักงานขอให้เอารูปตัวเองออก

> เปิดชีต → แท็บ **Announcements** → คลิกแถวประกาศนั้น →
> เมนู **🏪 HR Hub → 📢 ประกาศ → 🗑️ ถอนรูปออกจากประกาศ (แถวปัจจุบัน)**

ระบบจะลบทั้งลิงก์ในชีต **และย้ายไฟล์จริงลงถังขยะของ Drive** (กู้คืนได้ 30 วัน)

⚠️ **การลบไม่ย้อนเวลา** — ถ้าเคยเผยแพร่ไปแล้ว คนที่คัดลอกลิงก์เก็บไว้ก่อนหน้านี้
อาจยังมีสำเนารูปอยู่ การถอนรูปหยุดการเข้าถึงในอนาคตเท่านั้น

---

## 🔴 เรื่องที่เจ้าของร้านต้องตัดสินใจ ก่อนเปิดใช้จริง

รูปประกาศของร้านส่วนใหญ่จะเป็น **รูปพนักงาน** — รูปทีม รูปอบรม รูปงานเลี้ยง
รูปแนะนำพนักงานใหม่ ทุกรูปเหล่านี้จะกลายเป็นลิงก์สาธารณะถาวร

ต้องตกลงกันให้ชัดก่อนว่า

1. **ขอความยินยอมพนักงานอย่างไร** — เซ็นครั้งเดียวตอนเข้างาน หรือถามเป็นครั้ง ๆ
2. **พนักงานลาออกแล้วรูปเก่าเอาออกไหม** — ถ้าเอาออก ต้องเพิ่มขั้นตอนนี้ในกระบวนการลาออก
3. **ประกาศหมดอายุแล้วลบรูปด้วยไหม** — ตอนนี้ระบบ**ไม่ได้**ลบให้อัตโนมัติ

ข้อ 3 ยังไม่ได้ทำในรอบนี้ ดูหมายเหตุท้ายเอกสาร

# ส่วนที่ 2 — สำหรับคนดูแลระบบ

## รูปเก็บที่ไหน

โฟลเดอร์ Drive ชื่อ **"รูปประกาศ HR Hub"** ที่สคริปต์สร้างเอง
id เก็บใน Script Properties คีย์ `ANNOUNCEMENT_IMAGE_FOLDER_ID`

ชีตแท็บ `Announcements` เก็บ 2 คอลัมน์

| คอลัมน์ | เก็บอะไร |
| --- | --- |
| `imageUrl` | URL สำเร็จรูป (คอลัมน์เดิม ใช้กับการ์ด Flex ในแชท) |
| `imageFileId` | **file id ของ Drive** — คอลัมน์ใหม่ ★ คือประกันชีวิตของฟีเจอร์นี้ |

## ★ ทำไมต้องเก็บ `imageFileId` แยก

`https://drive.google.com/thumbnail?id=...&sz=w...` **ไม่ใช่ API ที่ Google รับรอง**
ถ้าวันหนึ่งมันเปลี่ยนรูปแบบหรือเลิกให้บริการ ประกาศทุกฉบับจะรูปหายพร้อมกัน

เพราะเก็บ file id ไว้ต่างหาก การกู้คืนจึงเป็น

1. แก้ฟังก์ชัน `announcementImageUrl_()` ใน `apps-script/14_Media.js` ที่เดียว
2. เมนู **🏪 HR Hub → 📢 ประกาศ → 🔁 ออก URL รูปใหม่ทั้งหมด**

ได้ URL ชุดใหม่ทั้งระบบ **โดยไม่ต้องอัปโหลดรูปซ้ำแม้แต่ไฟล์เดียว**

## ★★ เพดาน w1590 — ตัวเลขที่วัดมาแล้ว อย่าเปลี่ยนโดยไม่วัดใหม่

ทดสอบด้วย `curl` กับไฟล์สาธารณะจริง 2 ไฟล์ (ต้นฉบับ 2.7 MB และ 2.9 MB) ผลตรงกันทั้งคู่

| ขอขนาด | ได้ไฟล์ |
| --- | --- |
| `w480` | 84 KB |
| `w1024` | 275 KB |
| `w1280` | 393 KB |
| `w1500` | 507 KB |
| `w1590` | 591 KB |
| **`w1600`** | **2,772,444 ไบต์ — เท่ากับไฟล์ต้นฉบับทั้งไฟล์ เป๊ะ ๆ** |
| `w2000` | เท่ากับต้นฉบับเช่นกัน |

**ตั้งแต่ `w1600` ขึ้นไป Drive เลิกย่อรูปแล้วส่งไฟล์เต็มมาแทน**
แปลว่า `w1600` คือค่าที่ **แย่ที่สุด** ในบรรดาที่เลือกได้ — แพงกว่า `w1280` ถึง 7 เท่า
บนอินเทอร์เน็ตของร้าน ระบบจึงใช้ **`w1280`** สำหรับหน้ารายละเอียด และบีบทุกค่าลงมาไม่ให้เกิน `w1590`

**ผลพลอยได้ด้านความเป็นส่วนตัว** — ไฟล์ต้นฉบับมี EXIF ครบ รวม**พิกัด GPS ที่ถ่ายรูป**
ส่วนภาพที่ Drive ย่อให้ถูกเข้ารหัสใหม่ การกันไม่ให้เกินเพดานจึงกันไม่ให้พิกัดหลุดออกไปด้วย

## ขนาดที่ใช้จริง

| ที่ใช้ | ขนาด | ประมาณ |
| --- | --- | --- |
| รายการในหน้าเว็บ | `w480` | 25–85 KB |
| hero ของการ์ด Flex ในแชท | `w1024` | ~275 KB |
| หน้ารายละเอียด | `w1280` | ~390 KB |

## ตรวจลิงก์ก่อนเผยแพร่ — ★ ห้ามเช็กแค่ "ได้ 2xx"

ทดสอบแล้วพบว่า **id ที่ไม่มีอยู่จริงบางแบบคืน HTTP 200 พร้อมหน้า HTML 900 KB**
ถ้าเช็กแค่รหัสสถานะจะผ่านฉลุยแล้วไปพังตอนขึ้นจอพนักงาน

ตัวชี้ขาดคือ **`Content-Type` ต้องขึ้นต้นด้วย `image/`** — ตรรกะนี้อยู่ใน
`announcementImageProblem_()` ใน `14_Media.js`

## ทำไมลิงก์แชร์ปกติของ Drive ใช้ไม่ได้

`https://drive.google.com/file/d/<id>/view` คืน **หน้าเว็บ HTML** ไม่ใช่ไฟล์รูป
LINE จึงไม่ยอม render เป็น hero — นี่คือสาเหตุที่คอลัมน์ `imageUrl` มีมานานแล้วแต่ไม่เคยมีใครใช้ได้จริง

## ยังไม่ได้ทำในรอบนี้

- **ลบรูปอัตโนมัติเมื่อประกาศหมดอายุ** — ตอนนี้ต้องถอนด้วยมือ
  ถ้าจะทำ ให้เพิ่มใน `09_Triggers.js` ตรวจ `expireAt` แล้วเรียกลบไฟล์
- **ลบรูปตอนพนักงานลาออก** — ระบบไม่รู้ว่ารูปไหนมีใครอยู่ในนั้น ต้องเป็นขั้นตอนของคน
- **ลบ EXIF ออกจากไฟล์ต้นฉบับที่เก็บใน Drive** — ตัวที่เสิร์ฟจริงถูกย่อและเข้ารหัสใหม่แล้ว
  แต่ไฟล์ต้นฉบับในโฟลเดอร์ยังมี EXIF ครบ (โฟลเดอร์นั้นไม่ได้แชร์สาธารณะ มีแต่ไฟล์ในนั้นที่แชร์)
