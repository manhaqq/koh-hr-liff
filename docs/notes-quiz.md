# ระบบข้อสอบ/แบบฟอร์ม — บันทึกการออกแบบ

ไฟล์เดียวที่เป็นเจ้าของฟีเจอร์นี้คือ `apps-script/13_Forms.js`
หน้าจออยู่ใน `reports.html` เดิม (รายงาน R11/R12) ไม่มีหน้า LIFF ที่ 9

---

## สิ่งที่ต้องทำก่อนใช้งานจริง (มีคนต้องกด)

1. **สำรองชีตทั้งไฟล์ก่อน** (เมนู 🏪 HR Hub → 💾 สำรองข้อมูล → สำรองข้อมูลเดี๋ยวนี้)
2. เปิด Apps Script แล้วรัน **`ensureFormsSheets()`** หนึ่งครั้ง จะได้
   - แท็บใหม่ 3 แท็บ `Forms` `FormItems` `FormResponses`
   - คอลัมน์ `updatedAt` ต่อท้ายแท็บ `AppGuide`
   - แถว `R11` `R12` ต่อท้ายแท็บ `Reports`
   - ข้อสอบตั้งต้น 32 ข้อในแท็บ `FormItems`
3. **อ่านทวนข้อสอบทั้ง 32 ข้อในแท็บ FormItems** แล้วแก้ให้ตรงกับคู่มือฉบับจริง
4. เปลี่ยน `status` ของแถว `F001` ในแท็บ `Forms` จาก `off` เป็น `on`

ข้อ 3 ไม่ใช่พิธีกรรม — ดูหัวข้อ “ข้อสอบตั้งต้นมาจากไหน” ด้านล่าง

## ทำไมเซิร์ฟเวอร์เป็น state machine

ตัวเลือกที่ง่ายกว่าคือส่งข้อสอบทั้งชุดลงไปที่เครื่อง ให้ทำเสร็จแล้วค่อยส่งกลับมาตรวจ
รอบเดียว ซึ่งเร็วกว่าและเขียนง่ายกว่า แต่แลกมาด้วยสามอย่างพร้อมกัน

| ปัญหา | ผลจริง |
| --- | --- |
| เฉลยลงไปถึงเครื่องก่อนตอบ | ดัก response ครั้งเดียวได้เฉลยทั้งชุด แล้วส่งต่อกันในกลุ่มไลน์ |
| “ห้ามย้อนกลับ” เป็นแค่ UI | ใครยิง request เองข้ามได้ทันที |
| ทำค้างแล้วหาย | โทรเข้าหรือแบตหมด = เริ่มใหม่หมด ซึ่งคนจะไม่ทำรอบสอง |

ทางที่เลือกคือเก็บสถานะทั้งหมดไว้ฝั่งเซิร์ฟเวอร์ และให้ `quiz_answer`
คืน **ผลการตรวจ + คำถามข้อถัดไป ในคำตอบเดียวกัน**
จึงยังเป็น **1 รอบเครือข่ายต่อ 1 ข้อ ไม่ใช่ 2** ทั้งที่ได้คุณสมบัติทั้งสามข้อ

ผลข้างเคียงที่ตั้งใจ: เปิดหน้าใหม่กลางคันแล้วระบบพากลับมาที่ข้อเดิมเอง
เพราะไม่มีอะไรค้างอยู่ที่ client เลย ตัวแปร `QZ` ใน `reports.html`
ถือแค่ข้อปัจจุบันข้อเดียว

### ราคาที่ต้องจ่าย และวิธีที่ทำให้ถูกลง

รีวิวเชิงวิพากษ์ชี้ถูกว่า การเขียนแถวทุกข้อจะทำให้ `updateRow` เด้งเวอร์ชันแคช
ของแท็บ `FormResponses` ทิ้งทุกครั้ง ถ้าข้อถัดไปต้องอ่านทั้งแท็บใหม่เพื่อหาแถวตัวเอง
ต้นทุนต่อข้อจะโตตามจำนวนแถวสะสม (60 คน × 10 ข้อ × ทำซ้ำ ≈ หลายร้อยแถวต่อรอบ)
ฟีเจอร์จะดีในสัปดาห์แรกแล้วใช้ไม่ได้ในปีที่สอง

จึงเก็บสถานะรายครั้งไว้ใน `CacheService` แยกต่างหาก (คีย์ `atq_<attemptId>`, 6 ชม.)
เส้นทางปกติของ `quiz_answer` จึง **ไม่อ่านแท็บ FormResponses เลย** —
อ่านจากแคชแล้วเขียนเซลล์ `answers` เซลล์เดียว การอ่านทั้งแท็บเกิดแค่ตอน
`quiz_start` และตอนแคชหลุด ซึ่งเป็นทางสำรองที่ยังทำงานถูกต้องอยู่

## โครงข้อมูล

### Forms — HR พิมพ์เอง
`formId, type, title, description, audience, audienceValue, drawRules, passMark,`
`retakePolicy, cooldownHours, shuffle, showExplain, openFrom, dueDate, status, updatedAt`

- `type = quiz | survey` คือจุดเดียวที่ทำให้มันเป็นเอนจินทั่วไป
  `survey` คือเอนจินเดียวกันที่ `correct` ว่าง ระบบจึงข้ามการตรวจและไม่คิดคะแนน
- `audience` / `audienceValue` ส่งเข้า `matchAudience_()` (02_Data.js) ตรง ๆ
  ได้ `all/branch/dept/role/person` มาฟรีโดยไม่เขียนโค้ดใหม่
- `drawRules` เช่น `policy:4,vision:3,app:3` = จำนวนข้อต่อ pool ในเซลล์เดียว
  เว้นว่าง = ใช้ทุกข้อเรียงตาม `order`
- `status = off` คือสวิตช์ปิดฟีเจอร์ทั้งชุด

### FormItems — คลังข้อ
`qId, formId, pool, order, type, question, choiceA..choiceE, correct, explain,`
`sourceTab, sourceId, points, status, updatedAt`

`correct` และ `explain` **ไม่เคยออกจากเซิร์ฟเวอร์ก่อนผู้ใช้ commit คำตอบของข้อนั้น**
จุดบังคับคือ `publicItem_()` ซึ่งประกอบ object ใหม่ทีละฟิลด์ ไม่ได้ลบฟิลด์ออกจากแถวเดิม
— ตั้งใจให้เป็นแบบนี้ เพราะการลบฟิลด์ออกจะพลาดได้เงียบ ๆ เมื่อมีคนเพิ่มคอลัมน์ใหม่ทีหลัง

### FormResponses — ระบบเขียนเอง 1 แถว = 1 ครั้งที่ทำ
`attemptId, formId, empCode, name, dept, branch, attemptNo, startedAt, submittedAt,`
`status, qIds, answers, score, total, percent, passed, durationSec`

`answers` เป็น JSON object ในเซลล์เดียว เช่น `{"QP07":"B","QV12":"A,C"}` ยาวราว 200 อักขระ
จากลิมิตเซลล์ 50,000 ทำให้ไม่ต้องมีแท็บที่สี่ ไม่ต้องเขียนสองรอบต่อข้อ
และเซลล์ที่ขึ้นต้นด้วย `{` เป็นสูตรไม่ได้อยู่แล้ว จึงไม่เพิ่มพื้นผิว formula injection

## การผูกข้อสอบกับนโยบายต้นทาง

`sourceTab` + `sourceId` ชี้ไปแถวจริงในแท็บ `Handbook` หรือ `AppGuide` ได้สามอย่าง

1. **ตอบผิดแล้วกดอ่านนโยบายจริงได้ทันที** — ลิงก์สร้างฝั่งเซิร์ฟเวอร์ด้วย `liffUrl()`
   เพราะ LIFF ID อยู่ใน Script Properties ไม่ใช่ในหน้าเว็บ
   ใช้พารามิเตอร์ที่หน้านั้นอ่านได้จริงวันนี้ (`cat=` สำหรับคู่มือ, `g=` สำหรับคู่มือแอป)
   และแนบ `id=` ไปด้วยเป็นตะขอสำหรับวันที่หน้าเหล่านั้นรองรับการ deep link รายหัวข้อ
2. **รายงานความครอบคลุม** — `formsCoverageReport()` บอกว่าหัวข้อไหนยังไม่มีข้อสอบ
   และ `sourceId` ไหนชี้ไปแถวที่ไม่มีอยู่จริง
3. **ธง “นโยบายเปลี่ยนแล้ว”** — ถ้า `updatedAt` ของแถวต้นทางใหม่กว่าของข้อสอบ
   แปลว่านโยบายถูกแก้หลังจากเขียนข้อนี้ ข้อนั้นอาจสอนสิ่งที่ไม่จริงแล้ว
   นี่คือข้อรับประกันความสอดคล้องจริง ๆ ของฟีเจอร์ ต้นทุนคือเทียบวันที่หนึ่งครั้งต่อข้อ

> ต้องมีคอลัมน์ `updatedAt` ในแท็บ `AppGuide` (`ensureFormsSheets()` เติมให้)
> และ HR ต้องแตะวันที่นั้นเวลาแก้เนื้อหา ไม่งั้นธงข้อ 3 จะไม่เคยขึ้น

**ต้นทางที่ไม่มีวันที่ = ไม่ตั้งธง** โดยตั้งใจ ดีกว่าฟ้องผิดทุกสัปดาห์จนคนเลิกอ่าน

### รายงานนี้ต้องไปอยู่ในอีเมล ไม่ใช่เมนูในชีต

รีวิวเชิงวิพากษ์ชี้ว่าเครื่องมือดูแลข้อสอบที่เป็น “เมนูในชีตซึ่งต้องเปิดคอมพิวเตอร์ถึงจะกดได้”
คือสิ่งที่ถูกกดครั้งเดียวแล้วไม่มีใครกดอีกเลย จึงออกแบบผลลัพธ์ให้เป็นข้อความไม่กี่บรรทัด
พร้อมแปะในอีเมลสรุปของ HR ผ่าน `formsCoverageDigest()`
(`showFormsCoverage()` ยังมีไว้เผื่ออยากดูทันที แต่ไม่ใช่ทางหลัก)

## ข้อสอบตั้งต้นมาจากไหน — และทำไมยังต้องมีคนอ่านทวน

32 ข้อใน `QUIZ_SEED_` เขียนด้วยมือจากเนื้อหาที่ **มีคนรีวิวแล้วและอยู่ในรีโปนี้จริง**

| pool | จำนวน | ที่มา |
| --- | --- | --- |
| `policy` | 12 | `manual/src/01-staff.html` (คู่มือพนักงานฉบับพกพา) และตาราง SLA ใน `00_Config.js` |
| `vision` | 10 | โครงหมวดหลัก 5 หมวดของคู่มือพนักงาน และหลักการ 0 บาทใน `README.md` |
| `app` | 10 | หน้าคู่มือแอป myHR Cloud ในระบบ และหัวข้อ “เจอปัญหา ทำยังไง” ในคู่มือพนักงาน |

**ไม่ให้ LLM แต่งข้อสอบเอง** เพราะไม่ใช่ 0 บาท และจะกลายเป็นการเอาข้อความนโยบาย
ที่ไม่มีใครรีวิววางตรงหน้าพนักงาน 60 คนเหมือนเป็นของจริง

ด้วยเหตุผลเดียวกันนี้เอง คำถามทุกข้อจึงหลีกเลี่ยงตัวเลขที่ยังไม่ยืนยัน
(อัตราเบี้ยขยัน วันจ่ายเงินเดือน เวลาละหมาดที่แน่นอน) และถามเฉพาะสิ่งที่เอกสารในรีโประบุไว้ตรง ๆ
ถ้าอยากออกข้อสอบเรื่องเหล่านั้น ให้ HR เขียนเพิ่มเองในแท็บ `FormItems`

**และนี่คือเหตุผลที่แถว `F001` เกิดมาพร้อม `status = off`** — ระบบพร้อมใช้ตั้งแต่วันแรก
แต่ไม่มีใครเห็นข้อสอบจนกว่าจะมีคนอ่านทวนแล้วเปิดเอง

### การผูกต้นทางตอนใส่ข้อสอบตั้งต้น

`resolveSourceId_()` จับคู่ข้อสอบกับแถว Handbook/AppGuide จริงด้วยคำค้นหา
ถ้าจับคู่ไม่ได้จะ **ปล่อย `sourceId` ว่าง** ไม่ใช่เดา — ลิงก์ที่ชี้ผิดหลอกคนอ่าน
หนักกว่าไม่มีลิงก์ ข้อที่ยังไม่ผูกจะโผล่ในรายงานความครอบคลุมให้ HR เติมทีหลัง
หรือกด `formsRelinkSources()` ให้ลองจับคู่ใหม่หลังเติมเนื้อหาในคู่มือแล้ว

## ความปลอดภัยของคะแนน

คะแนนคือข้อมูลผลงานพนักงาน จึงใช้กติกาเดียวกับรายงาน R05/R06

- **ตรวจ role ซ้ำในโค้ด** ที่ `apiQuizTeamReport_()` ไม่เชื่อคอลัมน์ `audience`
  ในแท็บ `Reports` อย่างเดียว เพราะ HR แก้ชีตนั้นเองได้ ถ้าเผลอตั้งเป็น `ALL`
  คะแนนของทั้งแผนกจะหลุดถึงพนักงาน 60 คนทันที
- **แผนกว่างต้องไม่เห็นใครเลย** หัวหน้าที่ยังไม่ได้กรอกแผนกจะได้คำเตือน ไม่ใช่รายชื่อทุกคน
- **ส่งเฉพาะฟิลด์ที่หน้าจอวาดจริง** — R11 ส่งชื่อ/จำนวนครั้ง/คะแนนดีที่สุด/ผ่านหรือยัง/วันที่
  ไม่ส่ง `lineUserId` เบอร์โทร สถานะการจ้าง และไม่ส่ง `answers`/`qIds` ของใครเลย
- **เขียน AuditLog ทุกครั้งที่หัวหน้าดึงคะแนนของลูกทีม** (`QUIZ_TEAM_VIEW`)
- ไฟล์นี้อ้างอิงคนด้วย `empCode` เท่านั้น ไม่แตะ `lineUserId` แม้แต่ในบันทึก
  (`handleFormsApi_` รับพารามิเตอร์ `userId` ไว้ให้ครบสัญญา แต่ไม่ใช้โดยตั้งใจ)

“หัวข้อที่ทีมพลาดบ่อย” นับจำนวนครั้งที่ตอบผิดรวม ๆ ไม่ได้บอกว่าใครตอบอะไร

## เรื่องที่ตัดสินใจแล้วและเหตุผล

| เรื่อง | ที่เลือก | ทำไม |
| --- | --- | --- |
| สลับลำดับตัวเลือก | ไม่ทำ | `correct` เก็บเป็นตัวอักษร A–E การสลับต้องแปลงกลับทุกครั้ง เพิ่มจุดพังโดยได้ผลกันโกงน้อย |
| สลับลำดับ**ข้อ** | มีคอลัมน์ `shuffle` แต่ตั้งต้น `FALSE` | สุ่มในกลุ่มอยู่แล้ว การสลับข้ามกลุ่มทำให้อ่านกระโดดไปมา |
| ล็อกตอนบันทึกคำตอบ | ใช้ `LockService` script lock 10 วิ | กดปุ่มรัวสองครั้งจะอ่าน `answers` ชุดเดิมได้ทั้งคู่แล้วเขียนทับกัน คำตอบหายเงียบ ๆ |
| ปุ่มย้อนกลับระหว่างทำ | ไม่วาด **และ** เซิร์ฟเวอร์ปฏิเสธ | ถ้าวาดแล้วเซิร์ฟเวอร์ปฏิเสธ ก็เป็นได้แค่ปุ่มที่กดแล้ว error |
| แถบหมวดระหว่างทำข้อสอบ | ซ่อน | แตะโดนชิปหมวดหนึ่งครั้งจะเด้งออกจากข้อสอบกลางคัน |
| หน้าสรุป | โชว์เฉพาะข้อที่ตอบผิด | สั้นกว่าและเป็นสิ่งเดียวที่มีประโยชน์ต่อคนอ่าน |

### สิ่งที่ยังไม่ทำ

- **ไม่มีการส่งข้อความแจ้งเตือนใด ๆ** — ไม่มี push, multicast หรือ broadcast ในไฟล์นี้เลย
  ถ้าอยากบอกพนักงานว่ามีข้อสอบใหม่ ให้ลงเป็นประกาศแล้วใช้จุดแดงตามกลไกเดิม
- ยังไม่มีหน้าจอให้ HR แต่งข้อสอบ — พิมพ์ในชีตเหมือน Reports/Handbook
- `type` ของข้อรองรับ `single` / `tf` / `multi` แต่ข้อตั้งต้นเป็น `single` ทั้งหมด
- ยังไม่มีการทดสอบโหลดจริง ข้อจำกัด 30 execution พร้อมกันของ Apps Script
  ยังเป็นข้อสมมติ ไม่ใช่ตัวเลขที่วัดแล้ว — ถ้าจะบังคับทั้งร้านทำภายในวันเดียว ควรวัดก่อน
