# แผงควบคุม HR (admin.html) — สิ่งที่ต้องรู้

หน้าเว็บสำหรับ **หัวหน้าแผนก / ทีม HR / ผู้ดูแลระบบ** ใช้ทำงาน 3 อย่างจากโทรศัพท์
ได้แก่ ตอบเรื่องพนักงาน · อนุมัติใบลา · แก้ตารางกะรายวัน

| ส่วน | ไฟล์ |
| --- | --- |
| หน้าเว็บ | `admin.html` (ใช้ `app.js` / `app.css` ร่วมกับอีก 8 หน้า) |
| หลังบ้าน | `apps-script/12_AdminApi.js` — ทางเข้าเดียวคือ `handleAdminApi_()` |
| LIFF ID | `config.js` → `LIFF.admin` และ Script Property `LIFF_ID_ADMIN` |

## ทำไมต้องมีหน้านี้

งานของ HR ทั้ง 28 อย่างในระบบนี้อยู่ในเมนูของ Google Sheets ทั้งหมด
และ **แอป Google Sheets บนมือถือไม่แสดงเมนูที่เขียนเอง และไม่แสดงกล่องโต้ตอบเลย**
แปลว่าเดิม HR ทำงานจากโทรศัพท์ไม่ได้แม้แต่อย่างเดียว ต้องกลับไปนั่งหน้าคอมเสมอ

เรื่องที่ใหญ่กว่านั้น: ชีตไม่มีระบบสิทธิ์ — ใครที่แก้ชีตได้ก็ปลดพนักงานได้
อ่านเรื่องร้องเรียนลับได้ และยิงข้อความฉุกเฉินจนโควตาหมดได้
หน้านี้คือสิ่งที่ทำให้ **ถอนสิทธิ์แก้ชีตของหัวหน้ากะ** เป็นไปได้จริงโดยที่เขายังทำงานได้

### 1. สร้าง LIFF ID ใหม่

LINE Developers Console → เลือก Provider → ช่อง **LINE Login** (ไม่ใช่ Messaging API)
→ แท็บ **LIFF** → **Add**

| ช่อง | ค่า |

| Size | **Full** |
| Endpoint URL | `https://manhaqq.github.io/koh-hr-liff/admin.html` |
| Scopes | `profile`, `openid` (ไม่ต้องเปิด `chat_message.write`) |
| Bot link feature | Off |

จะได้ LIFF ID หน้าตาแบบ `2011171874-xxxxxxxx` แล้วเอาไปใส่ **2 ที่**

1. `config.js` → `LIFF.admin` (แทนคำว่า `PASTE_ADMIN_LIFF_ID`)
2. Apps Script → ⚙️ Project Settings → Script Properties → คีย์ `LIFF_ID_ADMIN`

> ที่ 2 ใช้สร้างปุ่มในการ์ด "ติดต่อ HR" ถ้าไม่ใส่ ปุ่มจะไม่โผล่ (ตั้งใจให้เป็นแบบนั้น
> — พนักงานทั่วไปไม่ควรเห็นปุ่มที่กดแล้วเด้ง error)

### 2. ★ ทดสอบล็อกอินบนคอมก่อน แล้วค่อยถอนสิทธิ์แก้ชีต

เปิด `https://liff.line.me/<LIFF_ID_ADMIN>` ใน Chrome บนคอมด้วยบัญชี LINE ของ HR
**การล็อกอิน LINE บนเว็บมักต้องสแกน QR จากมือถือ** ถ้าขั้นตอนนี้ใช้งานจริงไม่ได้
สำหรับ HR คนนั้น หน้านี้จะแทน workflow เดิมบนคอมไม่ได้ และจะถอนสิทธิ์แก้ชีตไม่ได้เลย
**ต้องยืนยันข้อนี้ก่อน** ค่อยไปทำขั้นถอนสิทธิ์

### 3. ตั้ง role ในทะเบียนพนักงาน

ชีต `Employees` คอลัมน์ `role` ต้องเป็น `supervisor` / `hr` / `admin`
คนที่เป็น `staff` เปิดหน้านี้ไม่ได้ (ทั้งฝั่งหน้าเว็บและฝั่งเซิร์ฟเวอร์)

### 4. ★ หัวหน้าแผนกต้องมีค่าในคอลัมน์ `dept`

หัวหน้าที่คอลัมน์ `dept` ว่าง จะ **ไม่เห็นข้อมูลของใครเลย** — ไม่ใช่เห็นทุกคน
นี่คือพฤติกรรมที่ตั้งใจ (เคยเป็นบั๊กสิทธิ์ของจริงที่แก้ไปแล้ว) หน้าจอจะขึ้นคำอธิบายให้เอง
ว่าต้องแจ้ง HR เติมคอลัมน์ `dept`

## 1) กล่องเรื่องถึง HR

- ตัวกรอง **ค้างอยู่ / เกินกำหนด / ทั้งหมด** พร้อมตัวเลข เรื่องเกินกำหนดถูกดันขึ้นบนสุดเสมอ
- แตะเรื่องเพื่ออ่านรายละเอียดและตอบ · หน้ารายการ **ไม่แสดงเนื้อความของเรื่อง**
  เพื่อไม่ให้เนื้อหาหลุดตาคนที่เดินผ่านหน้าจอ
- ช่องพิมพ์คำตอบ **เก็บ draft ลงเครื่องอัตโนมัติ** ปิดหน้าไปแล้วเปิดใหม่ข้อความยังอยู่

### ★ "ส่งแล้ว" กับ "ส่งแล้วแต่แจ้งเตือนไม่ถึงเขา" ไม่เหมือนกัน

ระบบนี้ไม่ส่งข้อความ push (โควตาฟรีมีแค่ 300/เดือน) ช่องทางเดียวที่บอกผู้แจ้งว่ามีคำตอบ
คือ **จุดแดงบนเมนู "ติดต่อ HR"** ของเขา หน้านี้จึงแยกผลลัพธ์ออกเป็น 3 แบบ

| หน้าจอบอกว่า | แปลว่า | ต้องทำอะไรต่อ |
| --- | --- | --- |
| 🟢 ส่งคำตอบแล้ว ติดจุดแดงเรียบร้อย | เขาจะเห็นคำตอบเมื่อเปิดเมนู | ไม่ต้องทำอะไร |
| 🟡 บันทึกคำตอบแล้ว แต่แจ้งเตือนไม่สำเร็จ | มักเพราะเขาบล็อก/ลบบัญชี OA ไปแล้ว | **ติดต่อเขาโดยตรง** แล้วค่อยกลับมากดปิดเรื่อง |
| 🟡 นิรนาม — ปิดเรื่องให้แล้ว | ระบบไม่มีทางติดต่อเขาเลย | ถ้าอยากให้รู้ผล ให้ประกาศแบบรวมผ่านเมนูประกาศ |

กรณีที่ 2 ระบบจะ **ไม่เปลี่ยนสถานะเป็น "ตอบแล้ว"** โดยเจตนา
เพราะถ้าเปลี่ยน เรื่องจะหลุดออกจากงานค้างและหายจากอีเมล 09:00 ทั้งที่ไม่มีใคร
ไปบอกผู้แจ้งเลยสักคน เขาจะนั่งรอคำตอบที่ไม่มีวันมาถึง

### เรื่องนิรนาม

ห้ามเปิดเผยตัวตนกับใครทั้งสิ้น — ระบบไม่ได้บันทึกชื่อไว้ตั้งแต่แรก
หน้านี้แสดงว่า "ไม่ระบุตัวตน" เสมอ และ **บอกตรง ๆ ว่าแจ้งกลับไม่ได้** ไม่แกล้งทำเป็นส่งได้

### ใครเห็นอะไร

| บทบาท | เห็นเรื่องของ | เห็นระดับความลับ |
| --- | --- | --- |
| หัวหน้าแผนก | เฉพาะคนในแผนกตัวเอง | เฉพาะ `normal` |
| HR / admin | ทุกคน | ทุกระดับ รวมนิรนาม |

### เรื่องเก่าจะไม่หายไปไหน

แท็บ `Tickets` โตขึ้นทุกวันและไม่มีวันเล็กลง (กฎหมายแรงงานให้เก็บ 2 ปี)
หน้านี้จึงอ่านแค่ **300 แถวล่าสุด** เพื่อความเร็ว — **แต่** ระบบจะไล่ตรวจคอลัมน์ `status`
ของแถวที่เก่ากว่านั้นด้วยเสมอ แล้วดึง **เรื่องที่ยังค้างอยู่** กลับมาแสดงให้ครบ
เรื่องที่ค้างมานานที่สุดคือเรื่องที่ยากที่สุดเสมอ — ระบบที่ลืมมันเงียบ ๆ แย่กว่าระบบที่ช้า

## 2) คิวอนุมัติลา

- ตัวกรอง **รออนุมัติ / ตัดสินแล้ว / ทั้งหมด** · ใบที่ถึงวันลาก่อนถูกดันขึ้นก่อน
- **กรณีไม่อนุมัติ ต้องพิมพ์เหตุผล** ระบบบังคับ — ปฏิเสธเฉย ๆ พนักงานก็เดินมาถามอยู่ดี
- อนุมัติแล้วระบบติดจุดแดงแจ้งผู้ขอให้ (ใช้โควตาข้อความ 0)

### ★ อนุมัติลาแล้ว ตารางกะ **ไม่** เปลี่ยนให้อัตโนมัติ

ตั้งใจให้เป็นแบบนี้ ถ้าการอนุมัติเขียนกะ `LV` ลงตารางเองจะกลายเป็น
"ทางเขียนที่สอง" เข้าไปในตารางกะ ซึ่งชนกับทั้งการสร้างตารางจากรูปแบบ
และตัวแก้ตารางในหน้านี้เอง แล้วจะไม่มีใครรู้ว่าแถวนั้นมาจากไหน

**หลังอนุมัติลา ให้ไปที่แท็บ "ตารางวัน" แล้วตั้งกะ `LV` เอง** พร้อมกับจัดคนมาแทนในคราวเดียว
ซึ่งเป็นสิ่งที่ต้องทำอยู่แล้ว และเห็นภาพรวมทั้งวันว่าใครว่าง

## 3) ตัวแก้ตารางรายวัน

แก้ **ทีละวัน ทีละแผนก** ไม่ใช่ตารางทั้งเดือนแบบลากวาง
เพราะงานจริงคือ *"คนนี้ลาป่วย ย้ายคนนี้มากะเช้า"* ไม่ใช่การวางแผนทั้งเดือน
(การสร้างตารางทั้งเดือนยังอยู่ที่เมนูชีต **🗓️ สร้างตารางกะจากรูปแบบ** เหมือนเดิม)

- แถบวันที่ 7 วัน กด ‹ › เลื่อนทีละสัปดาห์
- แตะชื่อคน → เลือกกะจากรายการ (รวม `OFF` และ `LV`) ใส่หมายเหตุได้
- ปุ่ม **"เลือกหลายคน"** สำหรับใส่กะเดียวกันให้หลายคนพร้อมกัน
- คนที่ **ยังไม่มีกะ** ก็แสดงในรายการด้วย ไม่งั้นคนที่หลุดจากตารางจะมองไม่เห็นเลย
- แก้ได้ครั้งละไม่เกิน **25 คน** ต่อการกดบันทึกหนึ่งครั้ง

### ★★ เรื่องที่สำคัญที่สุดของทั้งหน้านี้ — คำว่า `manual`

ตัวสร้างตารางจากรูปแบบ (`generateScheduleFromPattern`) จะ **เก็บแถวเดิมไว้ก็ต่อเมื่อ
คอลัมน์ `status` เป็นคำว่า `manual` ตัวพิมพ์เล็กเป๊ะ ๆ เท่านั้น**

เดิมคำนี้ต้องพิมพ์เองในชีต และมันปรากฏอยู่ในโค้ดที่เดียวกับในข้อความ dialog อีกบรรทัดเดียว
ไม่มีที่ไหนอีกเลยในทั้งระบบ **หัวหน้ากะที่แก้ตารางวันเสาร์แล้วไม่ได้พิมพ์คำนี้
จะถูกเขียนทับหายเงียบ ๆ ในการสร้างตารางรอบถัดไป ไม่มีคำเตือน ไม่มีทางย้อนกลับ**

**หน้านี้ตั้งคำว่า `manual` ให้อัตโนมัติทุกครั้งที่มีคนแก้** ไม่มีทางลืมได้อีก

### ผลข้างเคียงที่ต้องตามดู และวิธีจัดการ

พอ `manual` ถูกตั้งอัตโนมัติ แถวที่ถูกป้องกันจะ **สะสมขึ้นเรื่อย ๆ** ถ้าปล่อยไว้หลายเดือน
การสร้างตารางใหม่จะได้ตารางที่เป็นเศษของข้อยกเว้นเก่าปนกัน โดยไม่มีใครแยกออกว่า
แถวไหนคือข้อยกเว้นที่ตั้งใจ และแถวไหนคือการสลับกะครั้งเดียวเมื่อสามเดือนก่อนที่ลืมคืนค่า

ระบบจึงบันทึกไว้ให้ด้วยว่า **ใครแก้ และแก้เมื่อไหร่**

- ชีต `Schedule` มีคอลัมน์ใหม่ต่อท้าย 2 คอลัมน์: **`manualBy`** และ **`manualAt`**
  (ระบบเติมให้เองอัตโนมัติครั้งแรกที่เปิดแท็บ "ตารางวัน" — ไม่ต้องทำอะไร)
- ในหน้าเว็บ แถวที่เป็น `manual` จะขึ้นข้อความเล็ก ๆ ว่า *แก้เอง โดย … · วันที่ …*
- ในกล่องเลือกกะมีปุ่ม **"↩︎ คืนค่าให้ระบบสร้างทับได้"** สำหรับข้อยกเว้นที่หมดความจำเป็นแล้ว
  (กดแล้ว `status` กลับเป็น `planned` **แต่กะที่ตั้งไว้ไม่ถูกลบ**)

> **แนะนำ:** เดือนละครั้ง เปิดชีต `Schedule` เรียงตาม `manualAt` แล้วดูแถวที่เก่ากว่า
> 1 เดือน ถ้าไม่จำเป็นแล้วให้กดคืนค่าจากในแอป

### คำเตือนที่หน้าจอคำนวณให้

กล่องเหลือง "⚠️ ตรวจก่อนปิดวัน" จะขึ้นเมื่อเจอ

1. **มีคนถูกใส่ไว้ 2 แถวขึ้นไปในวันเดียวกัน** (กะซ้อน)
2. **ยังไม่มีกะ** — มีชื่อในแผนกแต่ไม่มีแถวของวันนั้น
3. **แถวที่รหัสกะว่าง** — พนักงานจะเห็นช่องว่างในตารางของตัวเอง

> ⚠️ **ข้อ 1 ยังเป็นแค่คำเตือน ไม่ได้บล็อกการบันทึก** เพราะยังไม่ได้ยืนยันกับเจ้าของร้านว่า
> **กะซ้อนในวันเดียวกันมีจริงในร้านหรือไม่** ถ้าไม่มีจริง ควรเปลี่ยนให้เป็น error ที่บล็อก
> ถ้ามีจริง (เช่น มาช่วยครึ่งกะ) ให้คงเป็นคำเตือนไว้แบบนี้ — **ต้องถามก่อนเปลี่ยน**

### ข้อจำกัดตามบทบาท

- หัวหน้าแผนก: เห็นและแก้ได้เฉพาะแผนกตัวเอง และเฉพาะ **วันนี้เป็นต้นไป**
  (แก้ย้อนหลัง = แก้ค่าแรงที่จ่ายไปแล้ว)
- HR / admin: เลือกแผนกได้ และแก้ย้อนหลังได้

### ถ้ามีคนแก้ชีตพร้อมกัน

ทุกครั้งก่อนเขียน ระบบจะ **ยืนยันซ้ำว่าแถวเป้าหมายเป็นของคนคนนั้นในวันนั้นจริง**
ถ้าไม่ตรง (เพราะมีคนแก้ชีตตรง ๆ หรือเพิ่งรันสร้างตารางใหม่) ระบบจะอ่านใหม่แล้วลองอีกครั้ง
ถ้ายังไม่ตรงจะ **ข้ามรายการนั้นแล้วบอกให้รีเฟรช** — ไม่มีทางเขียนทับกะของคนอื่น

## กด "ส่ง" ซ้ำเพราะสัญญาณไม่ดี

wifi ในร้านหลุดบ่อย หน้าเว็บค้าง แล้วคนจะกดส่งซ้ำ — เรื่องปกติ

หน้านี้แนบรหัสอ้างอิงไปกับทุกการบันทึก และเซิร์ฟเวอร์ **จำผลของรหัสนั้นไว้ 10 นาที**
กดซ้ำจะได้คำตอบเดิมกลับมา ไม่ตอบเรื่องซ้ำสองครั้ง ไม่อนุมัติใบลาซ้ำ

**ถ้าขึ้นว่าบันทึกไม่สำเร็จ กดปุ่มบันทึกอีกครั้งได้เลย** ปลอดภัยเสมอ

---

## ทุกอย่างถูกบันทึกใน AuditLog

| การกระทำ | `action` ในชีต AuditLog |
| --- | --- |
| ตอบเรื่อง | `TICKET_REPLY` |
| ติดจุดแดงไม่สำเร็จ | `TICKET_REPLY_BADGE_FAIL` |
| ตัดสินใบลา | `LEAVE_DECIDE` |
| แก้กะที่มีอยู่ | `SCHEDULE_EDIT` — **หนึ่งแถวต่อหนึ่งช่องที่เปลี่ยน** บันทึกค่า ก่อน → หลัง |
| เพิ่มกะใหม่ | `SCHEDULE_ADD` |

ช่อง `actor` เก็บ **รหัสพนักงาน** ของคนที่กด (ไม่ใช่อีเมล ไม่ใช่บัญชี LINE)

---

## สิ่งที่หน้านี้ **ไม่** ทำ

- ❌ ไม่ส่งข้อความ push เลยแม้แต่ครั้งเดียว (แจ้งเตือนด้วยจุดแดงอย่างเดียว)
- ❌ ไม่แสดง `lineUserId` ที่ไหนเลย — หลังบ้านไม่ส่งค่านี้ออกมาตั้งแต่ต้น
- ❌ ไม่เปิดเผยตัวตนของเรื่องนิรนามกับใครทั้งสิ้น
- ❌ ไม่สร้างตารางทั้งเดือน (ยังอยู่ที่เมนูชีตเหมือนเดิม)
- ❌ ไม่เขียนกะ `LV` ให้อัตโนมัติเมื่ออนุมัติลา
- ❌ ไม่ปลดพนักงาน ไม่แก้ทะเบียนพนักงาน ไม่ส่งข้อความฉุกเฉิน — งานเหล่านี้ยังอยู่ในชีต

## เวลามีปัญหา

| อาการ | สาเหตุที่พบบ่อย |
| --- | --- |
| เปิดหน้าแล้วขึ้น "ยังไม่ได้ตั้งค่า LIFF ID ของหน้านี้" | ยังไม่ได้ใส่ `LIFF.admin` ใน `config.js` |
| ขึ้น "หน้านี้สงวนไว้สำหรับหัวหน้าแผนกและทีม HR" | คอลัมน์ `role` ในชีต `Employees` ยังเป็น `staff` |
| หัวหน้าเปิดได้แต่ไม่เห็นข้อมูลใครเลย | คอลัมน์ `dept` ของเขาว่าง — ให้เติมแล้วรอ 3 นาที (แคช) |
| ปุ่มแผงควบคุมไม่โผล่ในการ์ด "ติดต่อ HR" | ยังไม่ได้ตั้ง Script Property `LIFF_ID_ADMIN` |
| ตอบเรื่องแล้วขึ้นว่าแจ้งเตือนไม่สำเร็จทุกคน | ยังไม่ได้สร้าง Rich Menu — เมนู 🎛️ Rich Menu > สร้าง/อัปเดตทั้งหมด |
| แก้ตารางแล้วขึ้น "ตารางถูกแก้จากที่อื่นพร้อมกัน" | มีคนแก้ชีตตรง ๆ หรือเพิ่งรันสร้างตารางใหม่ — รีเฟรชแล้วทำใหม่ |
| ขึ้น "เซิร์ฟเวอร์ตอบช้าผิดปกติ" | สัญญาณไม่ดี — กดส่งอีกครั้งได้เลย ระบบกันบันทึกซ้ำไว้แล้ว |
